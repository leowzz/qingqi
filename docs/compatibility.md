# 兼容性与协议线索

## 已确认的能力边界

当前实现为 BLE 广播采集、GATT 服务发现、标准信息白名单读取、RSSI 测量和一次重连验证；不主动发起配对，不进行车主鉴权或车辆控制。读取需要加密的标准特征时，Android 系统可能显示配对提示。没有已验证支持控车的车型。扫描、连接成功和应用层认证成功是三个不同结论。

## 静态观察来源

以下为对爱玛出行 Android 5.9.5（包名 `com.adb.useroperation`）的静态观察总结，分析工具为 REA 与 JADX 1.5.6。

样本 APK SHA-256：`d837e2f7e8a5da463d439e93afa570ed562b896ee2bac2c9c53be09f7926bb22`。

用于定位的类名均位于 `com.aimatech.adb_bluetooth_plugin`：

| 来源位置 | 观察 |
| --- | --- |
| `bridge.AdbBleBridgeImpl.initBluetooth` | 接收蓝牙名称、MAC、密钥、用户标识与类型，要求 MAC 和类型非空。 |
| `manager.AdbBleManager` | 按类型选择 V1、V2 或 V3Bind 分支；尚未建立车型与类型的对应表。 |
| `manager.AdbBleManager.getUUID` | 查找 UUID 文本包含 `adb1` 的 indication 特征和包含 `adb2` 的 write 特征。 |
| `device.AdbBleDeviceV2.firstSend` | 连接握手需要用户标识和蓝牙密钥等输入；公开 UUID 本身不足以完成认证。 |

仓库不分发原版 APK 或反编译结果。本说明只保留方法定位、样本摘要和观察总结，不包含密钥或本机分析路径。

## 当前识别方式及限制

`GattProfile` 按服务分别检查两类线索：

- ADB：UUID 文本包含 `adb1` 且支持 indication，以及包含 `adb2` 且支持 write / write without response。沿用旧版片段匹配，存在误匹配可能。
- FF78：完整 UUID `0000ff78-0000-1000-8000-00805f9b34fb` 下同时具有 `7800/7801/7802/7804` 的 write + notify 和 `7803` 的 notify；特征也要求完整 Bluetooth Base UUID，不跨服务实例拼接。缺少一项不匹配这条线索，但不代表设备不兼容。

这两类均不验证厂商身份、协议代际、车主认证或车型，不作为发送指令的依据。报告顶部汇总检查中发现的线索，保留两轮原始清单供比较。

### FF78 静态定位

同一 5.9.5 样本的 `lib/arm64-v8a/libapp.so` 包含 FF78 与 7800–7804 完整 UUID 字符串，同时包含 `package:aima_ble_core/aima_blue/` 下 vehicle services、bind、query、control、report 和 common algorithm 的 Dart 源文件路径字符串。说明后续应调查 Flutter AOT 路径，不能仅沿 Java `AdbBleManager` 推断所有设备。

这是本地二进制字符串观察，尚未恢复这些 UUID 与具体方法之间的调用关系；不能据字符串相邻位置指定各通道用途，也不能推定握手、密钥来源或报文格式。没有经过验证的 FF78 控车报文。

仍需验证：具体控制器、蓝牙模块、正常车主凭据获取方式、握手与回包、控制参数、遥测数据、后台感应解锁可靠性。实际设备名或 MAC 也不等同于车主身份。

## 如何提供兼容性反馈

使用仓库的车型兼容性模板，注明车型、年份、配置、手机系统、应用版本，以及官方 App 各功能的实际表现。说明新 App 到达了“扫描发现”“GATT 连接”“发现接口”中的哪一步。不要把官方 App 的成功记为轻骑的成功。

公开报告保留服务 UUID、特征属性和错误码即可；请移除真实 MAC、个人设备名、车架号和账号信息。不要上传认证材料。

## 完整检查范围（0.1.5-field）

- 保存扫描时最后一条广播快照：可连接标志、RSSI、PHY、服务 UUID、厂商数据、服务数据和原始字节。不是连续广播抓包。
- 两轮连接均枚举服务、实例、包含服务、特征属性和描述符 UUID；不读取描述符或订阅通知。重连比较包含实例 ID 和枚举顺序，有变化不等于协议改变。
- 首轮仅对白名单发起标准读取：`180A` 下的 `2A24/2A26/2A27/2A28/2A29/2A50`，`180F` 下的 `2A19`，`1800` 下的 `2A00/2A01`，以及 `1812` 下的 `2A4A/2A4B`。要求完整标准 UUID 和 READ 属性，最多 12 项。不会读取序列号、私有特征或 HID 按键报告 `2A33/2A4D`，不操作 HID 控制点。
- PnP 标识按 7 字节和小端字段解析厂商编号来源、厂商、产品及产品版本原值；保留未知来源，不推定车型或认证状态。参考 [Bluetooth SIG Device Information Service §3.9](https://www.bluetooth.com/wp-content/uploads/Files/Specification/HTML/DIS_v1.2/out/en/index-en.html)。外观码保留数值，HID 信息按 4 字节解析，报告描述作为二进制原始值保存；格式异常会明确标记。读取成功计数表示 GATT 请求成功，不保证内容有效。
- 标准电量仅在单字节且 0–100 时显示百分比，不推定其来源是动力电池。
- 首轮最多两次 RSSI 测量，第二轮最多一次。首次失败仍尝试第二轮，第二轮不重试标准读取。
- 同一时间仅一个 GATT 请求。连接 15 秒、服务发现 10 秒、单项读取 4 秒、信号测量 3 秒，总时限 90 秒。缺失回调时关闭该连接，避免将迟到结果归到后续操作；失败与未完成项目留在报告里。
- 0.1.4-field 使用 SQLite 保存全部检查和逐条过程日志，取消或退到后台会保存最终部分报告。系统杀进程后，已提交事件仍保留，下次启动将未完成会话标为中断；尚在后台写入队列中的事件不能保证保存。

实车仍需确认：该车是否广播这些标准信息、需要哪代私有协议及认证输入。静态分析与模拟回调测试不能证明车型兼容。

## 本地实测版数据结构

`diagnostics.db` 的 `user_version=1`：

- `devices`：用户选中的蓝牙地址、最后名称和最后检查时间；地址去重，不等同于已确认车辆身份。
- `sessions`：UUID、逻辑 `device_id`、设备名/地址快照、开始/结束时间、应用与系统版本、手机型号、备注、运行状态、结论和最终报告。`finished` 只表示检查结束，具体通过/失败看结论；意外中断没有已知结束时间。
- `events`：逻辑 `session_id`、单调时钟相对毫秒、阶段和事件正文。接口清单及原始字节保留在正文中，不从文本推断车型或私有协议。

逻辑关联在事务内验证，无物理外键。数据读写、迁移、导出共用一个后台串行队列。导出先关闭连接将日志归并到主库，复制独立数据库到 ZIP，再输出每份文本报告；无需携带 WAL/SHM 文件。历史每页 50 条，不限制总数、不自动删除。

旧版 SharedPreferences 历史在事务中迁移，以稳定 UUID 去重；迁移标记只在事务成功后更新，保留旧值。读取、写入或导出失败会显示失败，不显示为空或保存成功。
