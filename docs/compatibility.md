# 兼容性与协议线索

## 已确认的能力边界

当前实现为 BLE 广播采集、GATT 服务发现、标准信息白名单读取、RSSI 测量和一次重连验证；不主动发起配对，不进行车主鉴权或车辆控制。读取需要加密的标准特征时，Android 系统可能显示配对提示。没有已验证支持控车的车型。扫描、连接成功和应用层认证成功是三个不同结论。

## 静态观察来源

以下为对爱玛出行 Android 5.9.5（包名 `com.adb.useroperation`）的静态观察总结，分析工具为 REA 与 JADX 1.5.6。

样本 APK SHA-256：`d837e2f7e8a5da463d439e93afa570ed562b896ee2bac2c9c53be09f7926bb22`。

用于定位的类名均位于 `com.aimatech.adb_bluetooth_plugin`：

| 来源位置 | 观察 |
| --- | --- |
| `bridge.AdbBleBridgeImpl.initBluetooth` | 接收蓝牙名称、MAC、密钥、用户标识与类型，要求 MAC 和类型非空。 |
| `manager.AdbBleManager` | 按类型选择 V1、V2 或 V3Bind 分支；尚未建立车型与类型的对应表。 |
| `manager.AdbBleManager.getUUID` | 查找 UUID 文本包含 `adb1` 的 indication 特征和包含 `adb2` 的 write 特征。 |
| `device.AdbBleDeviceV2.firstSend` | 连接握手需要用户标识和蓝牙密钥等输入；公开 UUID 本身不足以完成认证。 |

仓库不分发原版 APK 或反编译结果。本说明只保留方法定位、样本摘要和观察总结，不包含密钥或本机分析路径。

## 当前识别方式及限制

`GattProfile` 检查 UUID 文本中是否同时出现上述片段和相应属性，仅返回“可能匹配”的提示。调用处按服务分别检查，要求候选指示和写入特征位于同一服务。仍不检查厂商身份，也不确认完整 UUID、协议代际或车辆型号，因此可能误匹配。

仍需验证：具体控制器、蓝牙模块、正常车主凭据获取方式、握手与回包、控制参数、遥测数据、后台感应解锁可靠性。实际设备名或 MAC 也不等同于车主身份。

## 如何提供兼容性反馈

使用仓库的车型兼容性模板，注明车型、年份、配置、手机系统、应用版本，以及官方 App 各功能的实际表现。说明新 App 到达了“扫描发现”“GATT 连接”“发现接口”中的哪一步。不要把官方 App 的成功记为轻骑的成功。

公开报告保留服务 UUID、特征属性和错误码即可；请移除真实 MAC、个人设备名、车架号和账号信息。不要上传认证材料。

## 0.1.3 完整检查范围

- 保存扫描时最后一条广播快照：可连接标志、RSSI、PHY、服务 UUID、厂商数据、服务数据和原始字节。不是连续广播抓包。
- 两轮连接均枚举服务、实例、包含服务、特征属性和描述符 UUID；不读取描述符或订阅通知。重连比较包含实例 ID 和枚举顺序，有变化不等于协议改变。
- 首轮仅对白名单发起标准读取：`180A` 服务下的 `2A24/2A26/2A27/2A28/2A29`，以及 `180F` 服务下的 `2A19`。要求完整标准 UUID 和 READ 属性，最多 12 项。不会读取序列号或私有特征。
- 标准电量仅在单字节且 0–100 时显示百分比，不推定其来源是动力电池。
- 首轮最多两次 RSSI 测量，第二轮最多一次。首次失败仍尝试第二轮，第二轮不重试标准读取。
- 同一时间仅一个 GATT 请求。连接 15 秒、服务发现 10 秒、单项读取 4 秒、信号测量 3 秒，总时限 90 秒。缺失回调时关闭该连接，避免将迟到结果归到后续操作；失败与未完成项目留在报告里。
- 最近 10 次报告保存在本机；手动取消或进入后台会保存部分报告。系统直接杀进程或断电时，正在进行的一次报告不能保证保存。

实车仍需确认：该车是否广播这些标准信息、需要哪代私有协议及认证输入。静态分析与模拟回调测试不能证明车型兼容。
